# CLAUDE.md — AI Assistant Guide for MyApp

## Project overview

Android app for **time-zone arbitrage research** — analyses overnight-drift / lead-lag relationships between international equity, crypto, FX, commodity, and volatility markets. Ranks trading pair opportunities and provides step-by-step execution playbooks.

**Two build systems** exist side-by-side:

| System | Location | Language | Purpose |
|---|---|---|---|
| Gradle + Compose | `app/` | Kotlin | Primary app — Material3, Compose, full feature set |
| Legacy (aapt+dx) | `legacy-build/` | Java | Fallback — builds without Google Maven (no internet required) |

## Build & run

### Compose app (primary) — requires Android SDK + Google Maven

```bash
# Generate wrapper then build
gradle wrapper --gradle-version 8.9
./gradlew assembleDebug
# Output: app/build/outputs/apk/debug/app-debug.apk
```

Or let GitHub Actions build it automatically on push.

### Legacy app (fallback) — builds in any Linux with apt packages

```bash
sudo apt install android-sdk android-sdk-platform-23 \
  android-sdk-build-tools dalvik-exchange
bash legacy-build/build.sh
# Output: dist/app-debug.apk
```

### Research data refresh

```bash
pip install yfinance pandas numpy
python research/lead_lag.py --years 5 --out app/src/main/assets/research.json
```

Or trigger the `Refresh Research Data` workflow from GitHub Actions.

## Architecture patterns

### Navigation
State-based sealed interface in `MainActivity.kt`. No Navigation Compose library — all navigation is driven by a single `var screen: Screen by mutableStateOf(Screen.Home)` with `BackHandler`.

### Data loading
`ResearchRepository` loads `research.json` from Android assets at startup using `org.json` (in the Android framework — no extra dependency). Uses `@Volatile` + double-checked locking for thread safety. Parsed once and cached.

### Data models (Research.kt)
- `ResearchData` — top-level container with generation metadata and list of pairs
- `PairResult` — per-pair metrics (beta, t-stat, Sharpe, equity curve, playbook)
- `Playbook` — per-pair execution detail (instrument, entry/exit rules, risks)
- `Verdict` — computed property: STRONG (|Sharpe| >= 1.0, |t| >= 3.0), OK (>= 0.5, >= 2.0), WEAK

### Charting
`EquityChart.kt` — custom Compose `Canvas` drawing. No external charting library.

## Key conventions

### Language
- **UI text**: Thai (ไทย) throughout — headings, verdicts, explanations
- **Code identifiers**: English (Kotlin/Java standard)
- **Research docs**: Thai with English technical terms

### Formatting helpers (HomeScreen.kt)
```kotlin
fun fmt2(v: Double): String   // "%.2f"
fun fmt3(v: Double): String   // "%.3f"
fun pct(v: Double): String    // "%.1f%%"  (v is 0-1 fraction)
fun bps(v: Double): String    // "%+.1f bps" (v is decimal, e.g. 0.0005)
```

### Package structure
- `com.example.myapp` — Compose app (Gradle)
- `com.example.hello` — legacy APK (manual build)
- `com.example.myapp.data` — data models + repository
- `com.example.myapp.ui` — Composable screens + chart
- `com.example.myapp.ui.theme` — Material3 theme

### Verdict thresholds
```
|Sharpe| >= 1.0  AND  |t-stat| >= 3.0  →  STRONG ("น่าเล่น",  green)
|Sharpe| >= 0.5  AND  |t-stat| >= 2.0  →  OK     ("พอได้",    yellow)
else                                    →  WEAK   ("อย่าเล่น", grey)
```

## CI / GitHub Actions

### `android.yml` — Android CI
- Triggers: every push and PR to all branches
- JDK 17 (Temurin) + Gradle 8.9 via `gradle/actions/setup-gradle@v4`
- Generates Gradle wrapper in CI (no wrapper jar committed)
- Uploads `app-debug-apk` artifact

### `research-data.yml` — Refresh Research Data
- Triggers: `workflow_dispatch` (manual) + weekly cron (Monday 06:00 UTC)
- Python 3.12 + yfinance/pandas/numpy
- Runs `research/lead_lag.py`, uploads JSON artifact
- Auto-commits updated `research.json` back to branch

## Common tasks

### Adding a new market pair
1. Add entry to `PAIRS` list in `research/lead_lag.py` (symbol, names, category)
2. Run `lead_lag.py` or trigger GitHub Actions workflow to regenerate `research.json`
3. For pairs with detailed playbook: add a `ROWS` entry in the JSON generation script with a `playbook` dict
4. No Kotlin/Java code changes needed — the app renders dynamically from JSON

### Modifying verdict thresholds
Edit `PairResult.verdict` in `app/src/main/java/com/example/myapp/data/Research.kt` and the parallel logic in `legacy-build/src/com/example/hello/MainActivity.java`.

### Rebuilding the legacy APK
```bash
bash legacy-build/build.sh
# Outputs dist/app-debug.apk, copies research.json from app/src/main/assets/
```
Requires: `android-sdk`, `android-sdk-platform-23`, `android-sdk-build-tools`, `dalvik-exchange` apt packages.

### Changing target SDK for legacy APK
Edit `android:targetSdkVersion` in `legacy-build/AndroidManifest.xml`. Current: 34.
